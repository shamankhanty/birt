## С чего начинать работу

1. `STATE.md` — актуальное состояние проекта, правила расчётов и периодов, рейтинг, МАХ и результаты контроля качества.
2. `OPEN_ISSUES.md` — только реально незакрытые вопросы и ожидаемые данные.
3. `methodology/README.md` — основные методологические инварианты проекта.
4. `config/` — реестры показателей, политика валидации и параметры import pipeline.
5. `app/` и `lib/` — основная логика интерфейса, данных и расчётов.
6. `baseline/` и `validation/` — технический baseline-lock и результаты проверок.
7. `tests/` — автоматические проверки.

## Принцип обновления

Новые выгрузки сначала проходят staging / parallel replay. Рабочие JSON не заменяются до успешного контроля `PASS / WARNING / FAIL`.

Основные команды:

- `npm run validate:refactor` — формальная валидация, расчётная и metadata-эквивалентность;
- `node --test tests/*.test.mjs` — полный набор Node.js-тестов;
- `python3 scripts/pipeline/adapter_selftest.py` — self-test staging adapters;
- `npm run pipeline:scan` / `npm run pipeline:stage` — intake и staging новых выгрузок;
- `npm run build` — полный build-gate перед публикацией.

## Публичный репозиторий

В репозитории не хранить пароли, токены, ключи API, `.env` и иные секреты. Исходные данные проекта считаются открытыми по решению владельца проекта; перед добавлением новых наборов всё равно необходимо исключать секреты и технические учётные данные.

Публикация рабочей версии дашборда выполняется только по отдельной команде владельца проекта.
