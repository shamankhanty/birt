## С чего начинать работу

1. `STATE.md` — актуальное состояние проекта, утверждённые правила расчётов и периодов, рейтинг, МАХ и результаты контроля качества.
2. `OPEN_ISSUES.md` — только реально незакрытые вопросы и ожидаемые данные.
3. `SOURCE_PACKAGE.md` — сведения о каноническом пакете v5.1.0 и статусе первичного импорта.
4. `methodology/README.md` — основные методологические инварианты проекта.
5. `config/` — реестр показателей, политика валидации и параметры import pipeline.
6. `app/` и `lib/` — интерфейс, данные и расчётная логика.
7. `baseline/` — технические snapshots и baseline-lock.
8. `scripts/` — pipeline обновления, проверки и сборки.
9. `tests/` — автоматические проверки.

## Принцип обновления

Новые выгрузки сначала проходят staging / parallel replay. Рабочие JSON не заменяются до успешного контроля `PASS / WARNING / FAIL`.

Основные команды:

- `npm run validate:refactor` — формальная валидация, расчётная и metadata-эквивалентность;
- `node --test tests/*.test.mjs` — полный набор Node.js-тестов;
- `python3 scripts/pipeline/adapter_selftest.py` — self-test staging adapters;
- `npm run pipeline:scan` / `npm run pipeline:stage` — intake и staging новых выгрузок;
- `npm run build` — полный build-gate перед публикацией.

## Публичный репозиторий

Не хранить пароли, токены, ключи API, `.env` и другие секреты. Исходные данные проекта считаются открытыми по решению владельца проекта; перед добавлением новых наборов всё равно необходимо исключать технические учётные данные и секреты.

Служебные `__pycache__/` и `*.pyc` в репозитории не хранятся.

Публикация рабочей версии дашборда выполняется только по отдельной команде владельца проекта.
