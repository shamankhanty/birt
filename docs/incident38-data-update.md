# Обновление данных раздела И38

Раздел И38 использует два независимых набора данных:

- `app/incident38-cities.json` — выгрузка по городам;
- `app/incident38-districts.json` — выгрузка по районам.

Оба JSON формируются из Excel-источников. Исходные книги не нужно включать в репозиторий.

## Загрузка новых выгрузок

Из корня репозитория выполнить:

```bash
python3 scripts/update_incident38_data.py \
  --cities "путь/к/городской_выгрузке.xlsx" \
  --districts "путь/к/районной_выгрузке.xlsx"
```

Скрипт находит заголовки и организации по содержимому, проверяет 14 специальностей, уникальность OID, число МО в сводной строке и суммы нормативов/слотов/квоты ЕПГУ по каждой специальности. Для каждой МО также сверяется исходный «Реальный процент для ЕПГУ» с отношением слотов ЕПГУ к общему нормативу (допуск 0,051 п. п.). Если исходные итоги или проценты не совпадают либо обнаружено пропущенное значение, скрипт завершится с ошибкой и не заменит опубликованные JSON. Запись двух файлов выполняется только после проверки обоих источников.

Для отчётов с 01.10.2026 и позднее интерфейс исключает из отображения OID предшественников, перечисленные в `config/mo-reorganizations.json`. Исходные выгрузки и их контрольные итоги сохраняются без изменений. Головная МО остаётся самостоятельной строкой; значения предшественников к ней не прибавляются. Срезы до даты реорганизации не меняются.

После успешного импорта обновить контрольные SHA файлов в `baseline/current-production-manifest.json`, открыть PR и дождаться проверок. Production обновляется только после merge в `main`.

В интерфейсе дата городской выгрузки и дата районной выгрузки выводятся независимо. При разных датах срезы не сравниваются напрямую. Для новой недели достаточно заменить два входных Excel-файла и снова запустить эту команду; интерфейс и расчёты менять не требуется.

## Динамика между обновлениями

Перед заменой выгрузок импортер сохраняет прежние агрегаты по OID (слоты ЕПГУ и общий норматив) в `app/incident38-history.json`. Архивный срез не перезаписывается при повторной загрузке той же даты. Более старые выгрузки не могут заменить новые. При обновлении до 20.11.2026 данные на 19.11.2026 сохранены в архиве.

Первое историческое сравнение взято из исходного коммита раздела: города 10.11.2026 → 19.11.2026, районы 12.11.2026 → 19.11.2026. Поскольку старые даты различаются, региональная дельта не рассчитывается. Сравнение каждой группы идёт по пересекающимся OID и выбранному типу МО; изменение доли сопровождается отдельными изменениями слотов и норматива. Старую детализацию по специальностям не используем из-за исправленной 20.11.2026 ошибки привязки профилей.

План И38 — 60% общего норматива; цель — 70%. Дефицит и число выполнивших план считаются по 60%, достижение цели показывается отдельно.

Выгрузки 19.11 и 20.11 проверены по OID. Оба среза используют привязку ФРМО на 19.11; 20.11 является новой датой отчёта. Для детской городской поликлиники № 5 (OID `1.2.643.5.1.13.13.12.2.16.1089`) доля выросла с 65,4% (3892/5955) до 96,8% (5766/5955), то есть на 31,5 п. п. после округления. При нулевом нормативе процент в источнике пустой; значение выше 100% допустимо.
