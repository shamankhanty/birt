# Непередающие OID в раскрытии ТВСП

В управленческой таблице раскрытие проблемной МО раньше показывало все плановые OID проблемного здания, а справа — число передающих. Теперь оно показывает только полные OID непередающих обязательных СП и подпись «Не передают: N».

Для текущих амбулаторных, стационарных ТВСП и КДЛ списки восстановлены из листа «Детализация по СП» исходников от 29.10.2026. Для всех 857 объектов проверены исходные плановые OID и количества; разность планового и передающего перечней совпала с отдельным исходным столбцом непередающих. Добавлены только поля missingUnitOids: числовые значения, даты, планы, сравнения и история не пересчитывались. Контрольная сумма манифеста обновлена только для обогащённого файла unit-data.json.

- Амбулаторные ТВСП: 458 объектов, 79 непередающих сочетаний «здание — СП».
- Стационарные ТВСП: 274 объекта, 112 непередающих сочетаний.
- КДЛ: 125 объектов, непередающих нет.
- Диагностика и СМП: первичный отчёт содержит статус здания без перечня непередающих СП. Показывается ID здания и явное отсутствие OID СП; плановые/передающие OID не выдаются за непередающие.

Контроль ГП №21 (OID МО ...1179): здание101896 — окончания OID734924,980367,980372, «Не передают:3»; здание28544 —402111,735135,743003,883022, «Не передают:4».

Недельный адаптер сохраняет missingUnitOids при следующей загрузке. Полный плановый перечень остаётся в технической детализации с подписью «Все обязательные OID СП». На телефоне раскрытие показывает счётчик и переносит каждый полный OID отдельной строкой.

Проверено: 305 Node-тестов, Python-тест адаптера, adapter selftest со staging, production/offline build, контрольные суммы текущего набора. Браузер: GP21 — ровно7 непередающих OID и счётчики3/4, desktop1536px/mobile390px.

Публикация по отдельной команде.
