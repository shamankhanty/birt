# Сентябрь 2026: пересчёт рейтинга МО, версия 2

Основание: поручение пользователя пересчитать сентябрь и опубликовать после успешных тестов. Старая версия зафиксирована от production-коммита `a1e175e2de3c0291afa374447c0372478df558f1`. Пересчёт методики не является динамикой деятельности медицинской организации.

## Результат

124 МО, шесть профильных групп. Полный обязательный набор имеют 108 МО; 16 получают предварительный диапазон без официального места. Статус «Лидер» получают 27 МО. Детальный воспроизводимый отчёт — `september-v2-results.json` рядом с этим файлом.

В разделе 04 по умолчанию открывается новая методика. Сохранены прежняя версия и её объединения. Каждая строка показывает старые и новые место и балл; раскрытие содержит причины, периоды, исходные компоненты и пропуски. Равные итоговые баллы дают одинаковое место в новой версии. Исходная версия сохраняет свой прежний порядок.

## Правила

Блоки: помощь — 70%, цифровые услуги — 20%, готовность — 10%. Показатель = min(100, факт / план × 100). Перевыполнение не компенсирует отставание сверх максимального балла показателя. Внутри помощи и услуг показатели равновесны.

Готовность: ТВСП — 50%, активность врачей — 25%, группа специальностей 500+ — 25%. В активности равновесны «хотя бы один СЭМД» и III уровень, где применимо. Все подтверждённые специальности 500+ равновесны внутри одной группы; добавление специальностей не увеличивает вес группы. При отсутствии применимой группы её вес распределяется среди остальных групп готовности. Неприменимый блок перераспределяется между применимыми блоками. Это не разрешено для отсутствующих данных.

Официальное место требует 100% подтверждённых обязательных показателей по известному профилю. При пропуске показывается диапазон: нижняя граница — только подтверждённые вклады, верхняя — максимально возможные вклады пропусков. Это не присвоение пропущенному факту нуля. Официальный балл, место и лидерство при пропусках отсутствуют. Явный нулевой знаменатель означает отсутствие случаев для оценки, а не провал.

«Лидер»: итог от 95, полный набор, каждый применимый показатель помощи исполнен не менее чем на 80% плана. Места сортируются по баллу внутри типа; дополнительный критерий по размеру МО не используется. Равные баллы имеют одинаковое место.

Профиль базируется на справочнике МО. Специальности 500+ включаются только при положительной численности в сентябрьской кадровой выгрузке. Отсутствие специальности не объявляется нулевым результатом; полнота относится к подтверждённому профилю. Кадровый показатель «хотя бы один СЭМД» обязателен для всех МО; III уровень — для МО III уровня.

## Источники и периоды

Компоненты оригиналов сохранены в `app/rating/september-source-components.json`, названия и SHA-256 — там же и в `september-v2-inputs.json`.

- Профилактические СЭМД: MAX(122; 228) отдельно по каждой МО из РЭМД 01.01–30.09, знаменатель — случаи ФОМС за тот же период. Это максимум, а не сумма. Пример Агрызской ЦРБ: MAX(9665; 5104) / 15236 = 63,435%. В прежнем рейтинге был числитель 9464. РЭМД сформирован 30.09 в 14:44, поэтому не объявляется окончательным потоком за все сутки.
- Стационар: (выписные эпикризы + эпикризы роддома) / случаи из одного оригинала ОМС 01.01–30.09. Не смешивается с несвязанными общими итогами РЭМД.
- ЕПГУ: оригинал за 01.09–30.09, сформирован 22.10; дата формирования не меняет период. Региональные контрольные суммы: 6684 / 6690 финальных статусов, 6077 / 6690 обработок за два рабочих дня. Это восстановление реально действующего блока услуг, отсутствовавшего в расчёте версии 1.
- Кадры: принятые полные сентябрьские наборы, сформированы 14.10. Октябрьские оперативные стоматологи не подставляются.
- ТВСП: принятый накопительный срез 01.01–30.09, компоненты `julyQuantity` из зафиксированного `monthly-mo.json`. Название legacy-поля `july` не означает июль: период берётся из заголовка набора.

Кадры и ЕПГУ относятся к полному месяцу, СЭМД и ТВСП — к накопительному сентябрьскому состоянию. Новая версия явно показывает это различие; чистый месячный поток СЭМД из накопительного MAX не вычитается.

11 строк оригиналов не входят в согласованный реестр рейтинга (частные и внешние организации); они сохранены в аудите, не присваиваются похожим названиям. Контекстное соответствие РКБ/Спасская сохранено из прежнего справочника только для отчётов случаев и явно отмечено. Контекстная запись Спасской не получает выдуманный OID; имеет неполные данные и не занимает официального места. Кадровая РКБ остаётся отдельной организацией.

## Что исключено

Амбулаторные случаи: принятый сентябрьский числитель отличается от оригинала РЭМД на 30.09, а согласованная пара числителя и знаменателя не подтверждена. До её восстановления показатель исключён целиком для всех МО. Это ограничение снижает охват блока помощи и раскрыто в интерфейсе.

Рождение/смерть — доступный принятый период август, полного сентября нет. КДЛ исключены по действующему решению. Октябрьские оперативные срезы не участвуют. Абсолютные объёмы без подтверждённого месячного плана также не добавляются.

## Воспроизводимость и проверка

`read-september-sources.py` читает оригиналы без изменения оперативных наборов. `freeze-september.mjs` фиксирует исходный состав и отказывается переписывать сентябрь из изменённых принятых наборов или иных оригиналов. Архив v1 не перезаписывается. `report-september.mjs` пересчитывает только фиксированные входы и отдельную политику v2. Обычный build не обновляет историю.

Архивные значения v1 намеренно содержат прежние методические ограничения. Они нужны для прозрачного сравнения, не используются как факты новой версии. Рейтинг объединений оставлен в архивной версии: новая методика объединений не вводилась.

Проверено перед публикацией: полная сборка, 317 регрессионных тестов, проверка неизменности 36 производственных наборов, 21 адаптер, эквивалентность расчётов и метаданных. Проверка интерфейса локального HTML: раскрытие Агрызской ЦРБ, фильтр неполных данных, семь стоматологий, переключатель архива, мобильный экран 390 px без выхода страницы по ширине. TypeScript: те же 19 ранее существовавших ошибок, новых нет. Общий валидатор сохраняет один прежний WARNING по неоднородности месяцев исходных наборов; версия 2 исключает августовские свидетельства явно.
