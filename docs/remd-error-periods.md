# Два периода ошибок РЭМД

Раздел «Ошибки РЭМД» содержит вкладки «Накопительно с начала года» и «Оперативно за неделю». В каждой вкладке доступны категории и медицинские организации.

- app/error-categories.json и app/error-organizations.json — действующий оперативный недельный срез. Его продолжают использовать сводка и справочные блоки заслушивания.
- app/error-cumulative.json — независимый накопительный источник с 1 января, включая organizationBreakdown. Начальный подтверждённый срез: 01.01.2026–13.10.2026, 15 567 378 отказа, 37 категорий, 324 организации. Источник указан в JSON.
- Даты срезов показываются явно; накопительный источник не считается актуальным на дату недельного отчёта.
- Не складывать недельные выгрузки: периоды могут пересекаться, а исправления и повторные попытки могут менять состав.
- До подключения отдельного маршрута обновления годовой источник обрабатывается штатным adapt_errors в изолированном staging-каталоге с фактическими start/end из заголовка Excel; полученный error-categories.json с organizationBreakdown сохраняется как app/error-cumulative.json. Обязательные поля: source, periodKind=cumulative, startDate, endDate.
- Не направлять годовую выгрузку в обновление рабочих недельных файлов. Перед обновлением накопительного JSON проверять начало 1 января и согласованность года/конца периода.
- Контроль: итог категорий = итог организаций + неатрибутированные = total; категории каждой МО = count; sourcePeriod = period; доля ошибок без знаменателя запросов остаётся null.
- Проверки: node --test tests/error-period-tabs.test.mjs и стандартные проверки FAST_UPDATE_PROTOCOL.md.
